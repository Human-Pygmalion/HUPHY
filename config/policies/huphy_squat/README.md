# huphy_squat — 제자리 스쿼트 정책 배포 꾸러미

HUPHY LegOnly 이족(모터 12 개)이 평지에 서서 **목표 골반 높이 h\* 를 따라 앉았다 일어서는** 정책입니다.
밀어도 버티고, 필요하면 발을 디뎌 자세를 되찾습니다. 시뮬레이터는 필요 없습니다.
`numpy` 와 `onnxruntime` 만 있으면 됩니다.

정책이 무엇을 보고 어떻게 학습됐는지, 그리고 성능 수치는 [`../../huphy_squat/README.md`](../../huphy_squat/README.md) 에 있습니다.

> [!WARNING]
> **고정 자세(fixed stand)는 반드시 이 꾸러미의 기본자세로 잡으십시오. 기존 Huphy 정책의 자세가 아닙니다.**
>
> 정책은 켜지는 순간 "지금 기본자세로 서 있다" 고 보고 움직이기 시작합니다. 행동 0 이 곧 기본자세이기 때문입니다.
> 고정 자세가 기본자세와 다르면, 첫 주기의 목표각이 고정 자세에서 기본자세 쪽으로 **한 번에 튑니다.**
> 기존 꾸러미(`pyg_stand_*`, `pyg_rough_main_20261012`)의 서기 자세로 고정해 두고 켜면 다음 각이 한 번에 바뀝니다.
>
> | 관절 (R, L 은 부호 반대) | 기존 서기 자세 | 이 꾸러미 기본자세 | 차이 |
> |---|---|---|---|
> | hip roll | 0 | +0.05 | 0.05 rad (2.9°) |
> | hip yaw | 0 | +0.0088 | 0.009 rad |
> | crank A | +0.1439 | +0.1070 | 0.037 rad |
> | crank B | −0.1469 | −0.1847 | 0.038 rad |
>
> 켜는 순서와 확인 방법은 [5 절](#5-기본자세-행동-오프셋)과 [6 절 6 번](#6-켜기-전-점검)을 보십시오.

## 1. 들어 있는 것

| 파일 | 내용 |
|---|---|
| `policy_5000.onnx` (**기본**) / `policy_4500.onnx` / `policy_4000.onnx` | 같은 학습의 체크포인트 세 개. 관측 정규화가 ONNX 안에 들어 있음 |
| `policy_*.pt` | 같은 체크포인트의 원본 (rsl_rl). 로봇에서는 안 씀 |
| `deploy_contract.json` | 입출력 명세: 관측 43 칸·행동 12 칸 정의, 기본자세, h\* 범위, 참조 입출력, 해시 |
| `policy_runner.py` | `SquatPolicy`: 센서값 + h\* → 모터 목표각. 직전 행동과 엔코더 이력을 안에서 관리 |
| `obs_adapter.py` | 관측 벡터 조립 / 행동 → 목표각 변환 (`policy_runner` 가 씀) |
| `example_loop.py` | 가짜 로봇으로 도는 50 Hz 루프 예제. 실제 로봇은 이걸 고쳐 쓰면 됨 |
| `motor_params.json` | 모터별 Kp/Kd, 토크 한계, T-N 곡선, 관절 범위, 기본자세 |
| `train_env_manifest.json` | 학습 조건 요약 (랜덤화 범위, 노이즈, 지연) |

체크포인트 세 개는 모두 같은 입출력을 씁니다. 파일만 바꾸면 되고, 처음에는 **5000** 을 쓰십시오.

| 체크포인트 | 높이 오차 (평균) | 50 N 밀기 넘어짐 | 정지 시 떨림 (목표각 변화 RMS) |
|---|---|---|---|
| **5000** | 7.7 mm | 0.7 % | 5.8 mrad |
| 4500 | 6.8 mm | 1.2 % | 6.4 mrad |
| 4000 | 8.7 mm | 0.5 % | 6.2 mrad |

## 2. 바로 확인

```bash
pip install -r requirements.txt
python3 policy_runner.py --all --self-test   # 참조 입출력 대조 (세 체크포인트)
python3 example_loop.py --seconds 20          # 가짜 로봇으로 배선·주기 확인
```

`--self-test` 는 이 기계에서 ONNX 가 학습 기계와 같은 답을 내는지 봅니다. 허용치는 1e-4 이고, 만든 기계에서의 차이는 약 2e-6 입니다.
**여기서 어긋나면 모터를 켜지 마십시오.**

## 3. 코드에 붙이기

```python
from policy_runner import SquatPolicy

pol = SquatPolicy.from_package(checkpoint=5000)
pol.self_test()
pol.reset()                                    # 로봇을 세울 때마다
h_cmd = pol.default_pose_height                # 0.8914 m 에서 시작

while True:                                    # 50 Hz (20 ms)
    targets = pol.inference(
        gyro=imu.gyro,                         # [rad/s] IMU 좌표계 (+x 앞, +y 왼쪽, +z 위)
        projected_gravity=imu.gravity_dir,     # 중력 방향 단위벡터, 똑바로 서면 (0, 0, -1)
        joint_pos=encoders,                    # {"R_hip_pitch_joint": rad, ...} 모터 12 개
        h_star=h_cmd,                          # 목표 골반 높이 [m]
    )
    for name, q in targets.items():
        driver[name].set_position(q)           # PD 는 드라이버가 (아래 6 절)
```

## 4. 목표 높이 h\* 주는 법

**h\* 는 센서로 재는 값이 아닙니다.** 로봇 쪽에서 "이 높이로 서라" 하고 정해 주는 숫자 하나입니다.
조이스틱, UI, 시나리오 등 어디서 와도 됩니다. 정책은 자기 높이를 IMU 와 엔코더로 스스로 판단합니다.

| 항목 | 값 |
|---|---|
| 단위 | **m** (mm·cm 가 아님) |
| 정의 | 바닥에서 **골반(base_link) 원점**까지의 높이. 무게중심도 IMU 높이도 아님 (IMU 는 원점보다 6.95 cm 아래) |
| 학습 범위 | 0.65 ~ 0.895 m. 밖의 값은 잘라서 넣고 한 번 경고함 |
| **권장 범위** | **0.70 ~ 0.891 m**. 0.65 m 를 주면 약 0.683 m 에서 멈춤 (넣어도 위험하지는 않음) |
| 시작 값 | **기본자세 높이 0.8914 m** (`pol.default_pose_height`) |
| 넣는 주기 | 매 주기(50 Hz) 넣음. 바뀌지 않아도 같은 값을 계속 넣으면 됨 |
| 바꾸는 법 | 학습 때는 3~6 초마다 계단식으로 바뀌었으므로 계단 입력도 견딤. **실기에서는 초당 0.1 m 이하로 천천히 바꾸기를 권장** (`example_loop.py` 의 `H_RATE`) |

높이별 정확도는 정지 상태에서 잰 |실제 − 목표| 입니다.

| h\* | 0.891 | 0.72 | 0.68 | 0.65 |
|---|---|---|---|---|
| 오차 | 4 mm | 15 mm | 22 mm | 33 mm |

0.71 m 아래에서는 발목 각도가 한계에 걸립니다. 그래서 로봇이 엉덩이를 약간 뒤로 빼고 앉습니다. 정상 동작입니다.

## 5. 기본자세 (행동 오프셋)

**기본자세** 는 `deploy_contract.json` 의 `default_pose_rad` 입니다 (`motor_params.json` 의 `default_rad` 도 같은 값). 이 값 하나가 세 곳에 그대로 쓰입니다.

1. **목표각의 기준점**: 목표각 = 기본자세 + 0.25 · 행동. 정책이 0 을 내면 목표각이 정확히 기본자세입니다.
2. **엔코더 관측의 기준점**: 관측에는 엔코더각 − 기본자세 가 들어갑니다.
3. **시작 자세**: 정책을 켜기 전에 로봇을 이 자세로 보내 둡니다. 이때 골반 높이 0.8914 m 가 첫 h\* 입니다.

| 관절 [rad] | R | L |
|---|---|---|
| hip pitch | −0.175 | +0.175 |
| hip roll | +0.05 | −0.05 |
| hip yaw | +0.008837 | −0.008837 |
| knee | +0.35 | −0.35 |
| crank A | +0.106983 | −0.106983 |
| crank B | −0.184691 | +0.184691 |
| (수동, 참고) ankle pitch / roll | +0.1752 / −0.0508 | 거울 |

- 무릎을 살짝 굽혀 골반은 똑바르고 발바닥은 수평인 자세입니다. 다리는 0.05 rad (약 2.9°) 바깥으로 벌렸고, 발 원점 간격은 33.4 cm 입니다.
- hip yaw 의 작은 값은 발끝을 정면으로 맞추는 값입니다. 크랭크 값은 벌린 발을 다시 수평으로 만드는 발목 롤 −0.05 를 냅니다.
- 발목은 수동 관절입니다. 정책은 발목 각을 내지 않고 크랭크 모터 각만 냅니다.

> **주의 — 기존 Huphy 꾸러미 (`pyg_stand_*`, `pyg_rough_main_20261012`) 와 오프셋이 다릅니다.**
> hip pitch 와 knee 는 같지만, hip roll·hip yaw·crank A/B 가 다릅니다.
>
> | 관절 (R) | 기존 꾸러미 | huphy_squat |
> |---|---|---|
> | hip roll | 0 | +0.05 |
> | hip yaw | 0 | +0.008837 |
> | crank A / B | +0.1439 / −0.1469 | +0.1070 / −0.1847 |
> | 발 원점 간격 | 24.7 cm | 33.4 cm |
>
> 기존 오프셋을 로봇 코드에 직접 적어 두었다면 **반드시 이 꾸러미 값으로 바꾸십시오.** 그대로 쓰면 정책이 엉뚱한 자세를 기준으로 움직입니다.
> `policy_runner.py` 를 그대로 쓰면 오프셋을 명세에서 읽으므로 문제가 없습니다.

## 6. 켜기 전 점검

1. **제어 주기 50 Hz.** 20 ms 마다 `inference` 를 한 번씩 부릅니다. 주기가 20 % 넘게 어긋나면 runner 가 한 번 경고합니다.
2. **드라이버 PD 게인**: `motor_params.json` 값을 그대로 설정합니다. 학습에 쓴 값이 실제 드라이버 게인입니다.
   - 학습에서는 ±20 % 로 흔들었습니다.
   - 위치 목표만 보냅니다. 속도 목표는 0, 피드포워드 토크도 0 입니다.

   | 모터 | Kp [N·m/rad] | Kd [N·m·s/rad] |
   |---|---|---|
   | hip pitch / hip roll (RS04) | 135 | 6 |
   | knee (RS04) | 130 | 6 |
   | hip yaw (RS03) | 75 | 4 |
   | crank A / B (RS03) | 60 | 2.7 |
3. **크랭크는 모터 각입니다.** 발목 피치·롤 각도가 아닙니다. 발목은 크랭크와 로드로 움직이는 수동 관절이고, 정책은 크랭크 모터 각을 보고 냅니다.
4. **관절 0 점과 부호**는 학습한 MJCF 모델 기준입니다.
   - L 관절은 R 의 거울이라 부호가 반대입니다. 예: 기본자세 무릎 R +0.35, L −0.35.
   - 축 방향은 `motor_params.json` 의 `joint_axis_in_parent_link` 를 보십시오.
   - 처음에는 로봇을 매달고 모터별로 +방향을 하나씩 확인하십시오.
5. **중력 방향 부호**: 똑바로 서면 (0, 0, −1) 입니다.
   - 위 방향 벡터를 넣거나 가속도 [m/s²] 를 그대로 넣으면, runner 가 리셋 직후 멈추고 알려 줍니다.
6. **시작 자세 — 가장 중요합니다.** 정책을 켜는 순서는 다음과 같습니다.
   1. 드라이버 PD 로 모터를 **이 꾸러미의 기본자세**(`pol.default_pose`, 5 절 표)로 천천히 보냅니다 (fixed stand).
      - 매달린 상태에서 기본자세를 잡은 뒤 내려놓아도 되고, 바닥에서 천천히 보내도 됩니다.
      - 기존 정책용 서기 자세 코드나 값을 다시 쓰지 마십시오.
   2. 양발이 바닥에 닿고, 몸통이 똑바르고(중력 방향 ≈ (0, 0, −1)), 로봇이 멈춰 있는지 봅니다.
   3. **엔코더각과 기본자세의 차이를 모터마다 확인합니다.** 모두 **0.05 rad 이내**여야 합니다.
      - 학습에서 리셋 자세는 기본자세 ± 0.05 rad 였습니다. 이보다 크게 벗어나 있으면 켜지 말고 1 로 돌아가십시오.
      - 0.15 rad 이상 차이 나는 모터가 있으면, 그 모터의 0 점·부호나 오프셋 값을 의심하십시오.
   4. `pol.reset()` 을 부르고, **h\* = 0.8914 m** (`pol.default_pose_height`) 로 정책을 켭니다.
      - 첫 주기부터 정책 목표각을 그대로 보냅니다. 고정 자세 목표와 섞거나 보간하지 마십시오. 학습에는 그런 구간이 없었습니다.
   5. 몇 초 동안 제자리에서 안정적으로 서는지 본 뒤에 h\* 를 천천히 바꿉니다.

   확인 코드 예:
   ```python
   q = read_encoders()
   err = {j: abs(q[j] - pol.default_pose[j]) for j in pol.joint_names}
   worst = max(err, key=err.get)
   assert err[worst] < 0.05, f"{worst} 가 기본자세에서 {err[worst]:.3f} rad 벗어남 — 정책을 켜지 마십시오"
   ```

## 7. 이 코드가 하지 않는 것

- **안전 정지.** 넘어짐 감지, 토크·온도 감시, 비상 정지는 로봇 쪽에서 하십시오.
  학습에서는 몸통이 70° 넘게 기울거나 발 말고 다른 곳이 바닥에 닿으면 에피소드를 끝냈습니다.
- **PD 게인 설정과 토크 제한.** 드라이버가 합니다.
- **관측 노이즈와 지연을 흉내 내는 것.** 이것들은 학습 때만 넣었습니다.
  자이로·중력·엔코더 노이즈, 관측 0~40 ms·명령 0~20 ms 지연, 엔코더 오프셋 ±0.015 rad 를 넣었으므로, 실기의 그 정도 오차는 견딥니다.

## 8. 알려진 한계

- **평지에서 양발을 디딘 상태로만 학습했습니다.** 공중에 들어 올린 상태는 학습하지 않았습니다. 들어 올릴 때는 정책을 끄십시오.
- 밀기는 최대 60 N (0.1~0.2 초) 로 학습했습니다. 그 이상은 보장하지 않습니다.
- 낮은 쪽 범위는 정확히 내려가지 않습니다 (4 절 표).
- 모든 수치는 시뮬레이션 결과입니다. 실기 검증은 아직 안 했습니다.

`verify_deploy.py` 는 학습 환경과 이 꾸러미 코드를 나란히 돌립니다.
